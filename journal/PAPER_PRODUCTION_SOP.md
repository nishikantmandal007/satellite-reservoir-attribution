### A1. Target tree (created during Phase 4; replaces `reports/manuscript/`)

```
manuscript/
├── main.tex                  # preamble + metadata + \input lines ONLY (< 150 lines)
├── sections/
│   ├── 00_abstract.tex
│   ├── 01_introduction.tex

│   ├── 04_results.tex
│   ├── 05_discussion.tex
│   ├── 06_conclusions.tex
│   └── 07_declarations.tex   # CRediT, AI declaration, competing interests, data availability, funding, acks
├── supplement/
│   ├── supplement.tex        # own compile target
│   └── sections/…
├── references.bib
├── cover_letter/
│   └── cover_letter.tex
├── responses/
│   └── round1/               # created when reviews arrive: response.tex + diff.pdf
├── figures_src/              # SOURCES — committed, never submitted
│   ├── *.drawio              # illustrations (draw.io native)
│   ├── *.svg                 # exported SVG source-of-record for every figure
│   └── README.md             # which script/diagram generates which figure
├── figures_pub/              # SUBMISSION EXPORTS — only files main.tex references
│   ├── fig01_studyarea.pdf
│   ├── fig02_pipeline.pdf    # etc. — sequential, descriptive, no collisions (fixes D16)
│   └── …
└── Makefile                  # `make paper` (latexmk), `make figures`, `make wordcount`, `make checks`
```

### A2. Migration steps (from the current 1,201-line monolith)
1. `git mv reports/manuscript manuscript` (history preserved).
2. Compile the monolith once; record page count and save the PDF as `baseline.pdf`.
3. Split at each `\section` boundary into `sections/NN_name.tex`; `main.tex` keeps
   documentclass, packages, front matter, and `\input{sections/...}` lines only.
4. Fix `\graphicspath{{figures_pub/}}` (kills the `../figures/` bug).
5. Rename figure files to the `figNN_slug` convention; update every `\includegraphics`.
6. `latexmk -pdf main.tex`.
**ACCEPT A:** new PDF page count == baseline; spot-diff pages 1, mid, last visually identical;
`grep -c input main.tex` ≥ 8; no `\section` remains in main.tex; build succeeds from a clean
clone with `make paper`.

### A3. Rules of the tree
- Nothing in `figures_pub/` is hand-edited — every file is regenerated by `make figures`
  from `figures_src/` or `src/` scripts. If you can't regenerate it, it doesn't ship.
- One figure = one source (either a matplotlib script function or one .drawio page). The
  `figures_src/README.md` table maps `figNN → generator` and is kept current (ACCEPT: every
  file in figures_pub has a row).
- `responses/` uses quote–reply–change format (Part C7); never edit a submitted round.

## PART B — SOP-F: FIGURES, GRAPHS, ILLUSTRATIONS

### B0. The format pipeline (memorize this)
**Author in vector, submit what the journal accepts.** Verified 2026-07-11:
- Elsevier (JoH): vector **EPS or PDF recommended; SVG is NOT accepted**; raster TIFF/JPEG;
  RGB preferred. ([artwork formats checklist](https://www.elsevier.com/about/policies-and-standards/author/artwork-and-media-instructions/artwork-formats-checklist))
- Therefore: **SVG (and .drawio) = source of record, committed to `figures_src/`.
  PDF = submission format in `figures_pub/`.** PNG 300 dpi only as review-convenience copies.
- draw.io exports PDF/SVG/PNG natively (`drawio -x -f pdf -e -b 10 -o out.pdf in.drawio`);
  it does NOT export EPS — irrelevant, since PDF is recommended by Elsevier anyway.

### B1. Journal geometry (design AT FINAL SIZE — the #1 figure mistake is designing big and shrinking)
Verified Elsevier values ([artwork sizing](https://www.elsevier.com/about/policies-and-standards/author/artwork-and-media-instructions/artwork-sizing)):
| Slot | Width | Use for |
|---|---|---|
| Single column | **90 mm** | simple panels, maps with one subject |
| 1.5 column | **140 mm** | most result figures |
| Double column | **190 mm** | multi-panel time series, the pipeline schematic |
Minimum text at printed size: **7 pt normal, 6 pt sub/superscript**. Raster minimums:
halftone **300 dpi**, combination **500 dpi**, line art **1000 dpi** (avoid raster entirely
where possible — vector everything except imagery/maps with satellite backdrops).

### B2. Track 1 — Data graphs (matplotlib)
1. **Canonize the style**: extract from `src/regenerate_figures_pub.py` into `src/pubstyle.py`:
   - Wong (2011) palette constants (already correct — keep hex codes exactly)
   - `mm(w, h)` figsize helper: `(w/25.4, h/25.4)` inches; presets `SINGLE=90`, `MID=140`, `FULL=190`
   - rcParams with fontsizes set for FINAL width (tick 7 pt, label 8 pt, panel-letter 9 pt bold)
   - `save_pub(fig, name)`: writes `figures_src/{name}.svg`, `figures_pub/{name}.pdf`,
     `figures_pub/png/{name}.png` (300 dpi) in one call
2. **Design rules (apply to every graph):**
   - One message per figure; if you need two sentences to say what it shows, split it
   - **Never two y-axes.** Two scales → two stacked panels sharing x
   - Stacked time-series panels share identical x-limits and tick positions
   - Uncertainty is always drawn (band/whisker), never caption-only
   - Direct-label series where possible; legend only when >2 series and labeling clutters;
     never a legend for a single series
   - Categorical color order fixed across ALL figures (Maithon=blue #0072B2,
     Panchet=orange #E69F00, Durgapur=green #009E73, observed=black, modeled=blue,
     uncertainty=20%-alpha fill) — a reader learns the mapping once
   - Recessive scaffolding: grid 0.5 pt light gray, spines top/right off
   - Panel labels (a), (b), (c) — 9 pt bold, upper-left inside axes
3. **ACCEPT per graph:** rendered at true width on screen (`inkscape --query-width` or open PDF
   at 100%) → all text legible and ≥7 pt equivalent; `pdffonts figures_pub/figNN.pdf` shows all
   fonts embedded (`emb=yes`); colorblind check passes (see B4); regenerable via `make figures`.

### B3. Track 2 — Illustrations & schematics (draw.io — the mandated tool)
1. **Canvas setup:** File→Page Setup→custom size = target width (e.g., 190×110 mm for the
   pipeline schematic). Design at final size — text placed at 7–9 pt IS the printed size.
2. **Style preset (create once as a draw.io custom style, use everywhere):**
   - Font: Helvetica (draw.io default renders reliably) 8 pt body, 9 pt bold titles
   - Wong palette hex codes as the custom color swatch; fills = 15–20% tints of the stroke
     color, strokes 1.5 pt, NO gradients, NO shadows (`shadow=0`), rounded=1 sparingly
   - Arrows: 1.5 pt, solid = data flow, dashed = validation/feedback paths; label every arrow
   - Align to grid (2 mm); equal box sizes within a rank; straight orthogonal edges
3. **Content rules for the Route-B schematic set:**
   - Pipeline figure: inputs (satellite/gauge/climate) → processing → mass balance →
     attribution → outputs, with the validation loops drawn as dashed returns; one page,
     max ~15 boxes — if more, split into overview + detail supplement figure
   - Every box label is a noun phrase; every arrow label a data object ("monthly area, km²")
4. **Export (both, every time):**
   `drawio -x -f svg -e -b 10 -o figures_src/figNN_slug.svg figNN_slug.drawio`
   `drawio -x -f pdf -e -b 10 --crop -o figures_pub/figNN_slug.pdf figNN_slug.drawio`
   Keep the `.drawio` source committed in `figures_src/` (never delete it).
5. **ACCEPT per illustration:** PDF opens at 100% with all text ≥7 pt legible; `pdffonts`
   shows embedded fonts (if draw.io outputs unembedded Helvetica, run
   `gs -o out.pdf -dPDFSETTINGS=/prepress -sDEVICE=pdfwrite in.pdf` to embed — verify again);
   B4 colorblind check passes; no text overlaps at final size.

### B4. Colorblind & accessibility check (every figure, both tracks)
1. Wong palette is CVD-safe by construction, but layered tints/greys are not automatically —
   simulate: `uv run python -c "from matplotlib import colors; ..."` is insufficient; use a
   simulator: open the PNG in an online CVD simulator OR
   `uv run python -m daltonlens.simulate` (pip: daltonlens) for deuteranopia + protanopia.
2. Identity must never be color-alone: line styles or direct labels differ per series.
3. **ACCEPT:** simulated deuteranopia version still fully readable; a grayscale print
   (`gs -sDEVICE=pdfwrite -sColorConversionStrategy=Gray`) remains interpretable.

### B5. Captions (written WITH the figure, not after)
Formula: **[Bold takeaway sentence.] [What is plotted, axes, units.] [Symbols/colors/bands
defined.] [n, period, uncertainty definition, data source.]**
ACCEPT: caption is understandable without reading the body text; every visual element on
the figure is defined in the caption; the takeaway sentence states a finding, not "Plot of X".

## PART C — SOP-W: WRITING THE PAPER (top-tier craft)

### C1. Order of writing (do not deviate)
**Figures → Results → Methods → Discussion → Introduction → Abstract → Title → Cover letter.**
Why: figures are the paper's skeleton — if the figure sequence doesn't tell the story alone,
no prose will fix it. Test before writing any prose: show the fig01–08 sequence + captions to
Dr. Ray; she should be able to state the paper's argument. ACCEPT: she can.

### C2. Two-stage drafting (every section)
Stage 1 — outline: bullet points, each bullet = one paragraph-to-be, annotated with the
figure/table/citation it will carry. Stage 2 — convert to prose: one idea per paragraph,
first sentence is the topic sentence, transitions carry logic (however/therefore/because),
citations integrated mid-sentence. **No bullet list survives into Results/Discussion/
Introduction/Conclusions** (Methods may keep genuine lists: criteria, data sources).

### C3. Per-section recipes
- **Introduction (4–6 paragraphs, funnel):** (1) the real-world problem with one striking
  quantified fact; (2) what is known — cite the closest competitors HERE, generously
  (Hou 2022, Vu 2022, Suresh 2024, Xie 2022, GERD papers, Humphrey & Gudmundsson — the 10+
  mandatory citations from NOVELTY_IMPACT_REVIEW §2); (3) the specific gap, stated so the
  competitors' existence makes the gap sharper, not embarrassing; (4) this study: the
  question, the estimand, and 3 contributions phrased as verifiable statements ("we
  quantify X to within Y"), never as adjectives ("novel", "comprehensive").
- **Methods:** past tense; every choice cited or justified in-line; the estimand defined
  BEFORE any model appears; reproducibility test — a reader with the repo could re-derive
  every table (this is literal: SOP-V7 executes it).
- **Results:** findings only, zero interpretation; every claim ends at a figure/table
  pointer; every number carries uncertainty; report the unfavorable results with the same
  prominence as favorable (the fold-level honesty in the old draft was praised — keep that DNA).
- **Discussion (5 paragraphs):** (1) answer the research question in the first sentence;
  (2) mechanism/physical interpretation; (3) comparison with the closest priors — where we
  agree, where we differ, why; (4) limitations as findings ("monthly aggregation makes our
  release estimates conservative"), never as apologies; (5) implications + one concrete
  next step.
- **Conclusions:** numbered, each maps 1:1 to an abstract claim and to a result section;
  nothing appears here that wasn't demonstrated.
- **Abstract (formula, ≤250 words for JoH/WRR; single paragraph, no labels):**
  context (1–2 sentences) → gap (1) → what we did (2) → quantified results with uncertainty
  (3–4 sentences, the paper's actual numbers) → implication (1). Write it LAST.

### C4. Craft rules reviewers reward
1. Claims ladder — verb matches evidence: **demonstrated** (direct measurement) >
   **showed/found** (analysis result) > **supported** (consistent multiple lines) >
   **consistent with** (association) > **suggests** (interpretation). Never climb a rung
   above the evidence; C3-type results live at "consistent with".
2. Numbers: always value ± uncertainty + n ("RMSE = 0.23 m, n = 19 dates"); significant
   figures match precision (no "0.5535" silhouette — "0.55").
3. Active voice default ("We reconstructed…"); passive only when the actor is irrelevant.
4. Sentence budget: average 15–22 words; one thought per sentence; if a sentence has two
   "and"s and a "which", split it.
5. Tense: past for what you did/found; present for established facts and figure pointers
   ("Figure 4 shows…").
6. Define every symbol at first use; maintain one notation table; never alternate synonyms
   for one concept (pick "release", don't rotate with "outflow"/"discharge").
7. No rhetorical inflation: delete "very", "clearly", "importantly", "it should be noted".

### C5. Anti-AI-tell pass (complements SOP-A disclosure — disclosed assistance, human voice)
Kill on sight: rule-of-three padding ("robust, scalable, and efficient"); AI vocabulary
(delve, showcase, underscore, comprehensive framework, paradigm, holistic, leverage-as-verb);
negative parallelism ("not only X but also Y" more than once per paper); em-dash chains;
uniform paragraph lengths (vary 3–8 sentences); "In conclusion" openers; hedging stacks
("could potentially suggest"). Method: read each section aloud (Nishi, literally); anything
you wouldn't say to Dr. Ray in a meeting gets rewritten. This pass is REQUIRED and is
Nishi's own-voice revision commit (SOP-A §3).

### C6. Cover letter (one page, four paragraphs)
(1) Title + what the study establishes in two sentences with the headline number;
(2) why it fits THIS journal (name recent related papers the journal published);
(3) the novelty statement (use NOVELTY_IMPACT_REVIEW §2's verified wording — no unverified
"first"); (4) declarations: preprint DOI, thesis provenance, AI disclosure, no simultaneous
submission, suggested reviewers (3–5, no collaborators, include one author of the closest
competing papers). ACCEPT: every factual claim in the letter also appears in the manuscript.

### C7. Response-to-reviewers SOP (for later rounds; file under `responses/roundN/`)
Quote–reply–change format per comment: verbatim reviewer text in a quote block → response
starting "We agree / We agree in part / We respectfully disagree because [evidence]" →
the exact manuscript change with location, or the evidence-based rebuttal. Every comment
gets an edit or a cited rebuttal — never silence, never "done" without showing the text.
Thank reviewers once, at the top, not per-comment. ACCEPT: a table maps every numbered
comment → response → diff location; the diff PDF (latexdiff) is attached.
